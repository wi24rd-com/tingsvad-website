The audit

Gudrun audits every morning. She has never found anything in order that was not suspicious.

Case file 30 · The audit

Gudrun’s daily audit

Every morning Gudrun goes through every page in both languages: the Worker fetches the page and checks the HTTP status and that the shared navigation was inserted, and a browser at the edge opens it, counts the key elements, reads any JavaScript errors and takes a picture. Gudrun’s comment is funny. The result is not.

Browser Run is free for a certain number of minutes a day, and the same minutes also have to draw link previews and the minutes’ PDF. So Gudrun only opens the pages that have changed. The Worker still fetches every page every morning and takes a SHA-256 fingerprint of the HTML; if the fingerprint matches a passed browser check within the last week, that check is reused and the page is marked unchanged. On Mondays every page is opened regardless, so a fault in the Worker or an API cannot hide behind an unchanged page.

If a page fails, Gudrun also writes it down in the site’s GitHub repo: one issue per day with failures, with the path, the HTTP status and what was missing, and she closes it herself when a later audit passes in full. The Workflow calls GitHub’s REST API with a token that may only touch issues in this one repo. Gudrun’s issues are public.

Gudrun also rehearses what goes wrong: the emergency drills show a timeout, a duplicate delivery and a dropped connection as simulations.
